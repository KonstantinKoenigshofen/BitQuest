Wie bildet eine Tabelle einen fachlichen Sachverhalt ab?

Eine Tabelle modelliert eine Menge gleichartiger Sachverhalte. Spalten beschreiben Attribute mit einem Datentyp. Eine Zeile beschreibt einen konkreten Fall. Lege zuerst fest, wofür eine Zeile steht. In rechnung kann sie eine Rechnung sein, in position eine einzelne Rechnungsposition.

Ein Primärschlüssel (primary key) identifiziert jede Zeile eindeutig und besteht aus einer oder mehreren Spalten ohne NULL. Ein Fremdschlüssel (foreign key) verweist auf einen eindeutigen Schlüssel in derselben oder einer anderen Tabelle. Mehrere Positionen dürfen dabei dieselbe Rechnungsnummer referenzieren. Diese Kardinalität bestimmt, wie viele Treffer ein Join liefern kann.

Wie übersetzt du eine Frage in SQL?

Die relationale Algebra beschreibt Operationen, die aus Relationen neue Relationen bilden. Selektion filtert Zeilen, Projektion wählt Attribute, und ein Verbund (join) verknüpft passende Zeilen. Vereinigung, Schnitt und Differenz kombinieren Relationen mit passenden Attributen. In der klassischen Algebra sind Relationen Mengen. SQL kann gleiche Ergebniszeilen mehrfach liefern, bis du beispielsweise mit DISTINCT Duplikate entfernst.

SQL ändert auch Struktur und Inhalt. CREATE TABLE, ALTER TABLE und DROP TABLE gehören zur Schemadefinition (data definition language, DDL). INSERT, UPDATE und DELETE ändern Daten (data manipulation language, DML). Prüfe bei UPDATE und DELETE die WHERE-Bedingung, denn sie bestimmt die betroffenen Zeilen.

Mit SELECT fragst du Daten ab. Wie viel wurde je Rechnung berechnet? FROM und JOIN bestimmen die Zeilenbasis. WHERE filtert vor dem Gruppieren. GROUP BY fasst Zeilen zu Gruppen zusammen, SUM summiert Werte darin, und HAVING kann ganze Gruppen filtern.

SELECT r.id, SUM(p.betrag) AS summe
FROM rechnung AS r
JOIN position AS p ON p.rechnung_id = r.id
GROUP BY r.id;

Ein INNER JOIN liefert nur passende Paare. Ein LEFT JOIN erhält zusätzlich linke Zeilen ohne Treffer. Ihre rechten Spalten enthalten NULL. Eine anschließende Bedingung wie WHERE p.betrag > 0 entfernt diese Zeilen wieder. Wenn du sie behalten willst, gehört die Eingrenzung der rechten Treffer in diesem Beispiel in die ON-Bedingung.

Was bedeutet NULL für Filter und Aggregate?

NULL kennzeichnet einen fehlenden oder unbekannten Wert. In der dreiwertigen Logik kann eine Bedingung wahr, falsch oder unbekannt sein. betrag = NULL ist unbekannt. Auch die Negation eines unbekannten Ergebnisses bleibt unbekannt. WHERE behält nur Zeilen mit wahrer Bedingung. Verwende IS NULL und IS NOT NULL, um auf fehlende Werte zu prüfen.

COUNT(*) zählt alle Zeilen seiner Gruppe, COUNT(betrag) nur die mit einem vorhandenen Betrag. SUM(betrag) lässt fehlende Beträge aus und liefert NULL, wenn kein summierbarer Wert vorliegt. Verwende COALESCE nur, wenn die fachliche Bedeutung des gewählten Ersatzwerts klar ist.

Warum kann ein Join eine Summe verfälschen?

Hat eine Rechnung zwei Positionen über 30 und 20 Euro sowie zwei Zahlungen, erzeugt ein Join beider Detailtabellen über die Rechnungs-ID vier Paare. Jede Position erscheint zweimal. Die Summe der Positionen wird dadurch 100 statt 50 Euro. SUM(DISTINCT betrag) würde zwar gleiche Beträge zusammenfassen, aber auch zwei tatsächlich verschiedene Positionen mit demselben Betrag nur einmal zählen.

Lege fest, welche Einheit du zählen oder summieren willst. Für Positionen und Zahlungen pro Rechnung aggregierst du jede Detailtabelle separat auf eine Zeile je Rechnung. Anschließend verbindest du die beiden Ergebnisse. Prüfe bei unerwarteten Totals an wenigen bekannten Schlüsseln, wie oft sie vor und nach dem Join auftreten.

Merksätze

  • Definiere zuerst, wofür eine Zeile im Ergebnis steht.
  • WHERE filtert Zeilen, GROUP BY bildet Gruppen und HAVING filtert Gruppen.
  • Joins können Zeilen vervielfachen. Unbekannte Filterergebnisse fallen bei WHERE heraus.

Verständnisfrage

Eine Rechnung enthält drei Positionen und zwei Zahlungen. Wie oft erscheint jede Position, wenn du beide Detailtabellen über die Rechnungs-ID verbindest, und wie erhältst du beide Summen korrekt?

Musterantwort

Jede Position erscheint zweimal, einmal je Zahlung. Der Join bildet sechs Paare. Aggregiere Positionen und Zahlungen getrennt nach Rechnungs-ID und verbinde erst die beiden Summen. So gehen die ursprünglichen Beträge jeweils genau einmal ein.
